# Аналитика «Колеса фортуны»

Сбор продуктовых метрик на Node.js и SQLite, без внешнего сервиса аналитики и
без cookie. Коллектор доступен через `/api/` на том же домене, что и сайт.

```
браузер → POST /api/e (пачками, sendBeacon)
            ↓
          collector
            ↓
      SQLite (WAL) → /api/stats и /api/sessions
            ↓
      ночной rollup → daily_rollup и daily_breakdown
```

## Идентификаторы

Аккаунтов в продукте нет. Идентификаторы браузера, вкладки, списка и сети
нужны для группировки событий; вместе с ними коллектор хранит IP и варианты
списка, которые могут содержать личные данные.

| Поле | Что это | Как получен | Живёт |
|---|---|---|---|
| `visitor_id` | браузер | UUID в `localStorage` | до очистки хранилища браузера |
| `session_id` | вкладка | UUID в `sessionStorage` | до закрытия вкладки |
| `wheel_id` | одинаковый список | первые 16 символов SHA-256 отсортированного списка | пока список не менялся |
| `org_id` | одна сеть | первые 16 символов SHA-256 от IP + постоянная соль | пока не сменился IP |

`wheel_id` считается от **отсортированного** списка, поэтому перемешивание не
меняет идентификатор. Помимо хеша, текущая версия также отправляет сами
варианты в `items_text`.

`org_id` группирует события с одним внешним IP. Это может быть офис, домашняя
сеть или общий выход VPN; считать такую группу одной организацией нельзя.

Связка `org_id` + `wheel_id` показывает одинаковые списки в одной сети, но
сама по себе не доказывает, что это одна команда.

## События

Общий конверт у всех: `ts`, `visitor_id`, `session_id`, `wheel_id`, `org_id`,
`is_invited`, `items_count`, `app_version`, `screen`, `lang`, `tz`,
`referrer_host`, `ua_browser`, `ua_os`, `is_mobile`, гео.

| Событие | Поля в `props` | Зачем |
|---|---|---|
| `page_view` | `has_params`, `load_ms` | визиты, доля пришедших по ссылке |
| `spin_start` | `duration_s`, `music`, `volume`, `sound_on`, `spin_index` | настройки на момент запуска |
| `spin_complete` | `spin_index`, `actual_ms` | доведённые до конца розыгрыши |
| `spin_abandon` | `progress_pct`, `spin_index` | ушли, не досмотрев |
| `decision` | `choice`, `items_left` | сценарий: раздача без повторов или просто рандом |
| `items_changed` | `before`, `after`, `source` | признак «пришёл со своей задачей» |
| `link_copied` | `items_count`, `music` | ключевая метрика виральности |
| `music_changed` | `from`, `to` | выбирают ли музыку осознанно |
| `duration_changed` | `to` | двигают ли ползунок |
| `audio_blocked` | `track` | у скольких людей не сработал автоплей |
| `error` | `message`, `source_line` | здоровье |

Вместе с событием сохраняются `items_text` (сами варианты, см. ниже),
`item_profile` (их признаки) и `ip`.

Типы событий и ключи `props` проверяются по белому списку: всё, чего нет
в списке, отбрасывается на входе.

## Интерактивная панель

`/api/dashboard` использует локально обслуживаемый Apache ECharts. Графики
занимают ширину панели без горизонтальной прокрутки и обновляют данные на месте.

- Ползунок под динамикой выбирает и масштабирует диапазон дат. Выбор меняет
  карточки, остальные графики и журнал сессий.
- Нажатие на столбец действий, музыки, решений или стран добавляет фильтр;
  повторное нажатие его снимает. На выбранном графике остаётся только
  выбранная категория. Фильтры можно сочетать и удалять по одному.
- Для точного периода есть поля дат. «Сбросить всё» возвращает 30 дней.
- Категория выбирает **сессии, где встречалось событие**. Остальные показатели
  учитывают все действия этих сессий в выбранном периоде.
- В блоке действий значения считаются в сессиях, а не смешивают число событий
  и уникальных посетителей.

API `/api/stats` и `/api/sessions` принимает общие параметры `days`, `from`,
`to`, `action`, `music`, `decision`, `country`. Даты включают обе границы.
Остальные показатели относятся к подходящим сессиям целиком; в массивах
`music` и `decisions` выбранная категория ограничивает свой график.
График динамики сохраняет общий временной контекст, когда его ползунок
выделяет поддиапазон.

## Журнал сессий

`/api/dashboard` → вкладка **Сессии**: список визитов и покадровая хронология
каждого. Видно порядок действий, паузы между ними и чем визит кончился.

```
14:32:01  зашёл на сайт          по ссылке с параметрами, 4 варианта
14:32:04  +3с  сменил музыку     Деревня дураков → Ну, погоди!
14:32:09  +5с  правил список     4 → 5 (вручную)
14:32:14  +5с  запустил вращение 20 с, Ну, погоди!
14:32:34  +20с розыгрыш завершён 20 с
14:32:35  +1с  решение           удалить победителя, осталось 4
14:32:51  +16с скопировал ссылку
```

### Поиск

Поле над списком ищет по содержимому списков без учёта регистра (подстрока)
и по началу IP, хеша сети, `visitor_id` или `session_id`. Например, `кос`
найдёт «Костя» в вариантах списка.

IP, `visitor_id` и хеш сети в отчёте кликабельны: клик фильтрует по этому
значению. Так из одной сессии за один шаг попадаешь во все визиты того же
браузера или сети.

| Параметр | Что делает |
|---|---|
| `q` | подстрока списка или начало идентификатора/IP |
| `ip` | точное совпадение по адресу |
| `org` | все визиты одной сети (хеш) |
| `visitor` | все визиты одного человека |
| `wheel` | все визиты с одним списком («команда») |
| `session` | хронология одного визита |

Фильтр применяется к сессии целиком: если совпало хотя бы одно событие,
показывается весь визит, а не одно событие.

```bash
curl -u admin https://wheel.rprokhorov.ru/api/sessions
curl -u admin -G --data-urlencode 'q=Костя' https://wheel.rprokhorov.ru/api/sessions
curl -u admin 'https://wheel.rprokhorov.ru/api/sessions?ip=203.0.113.7'
curl -u admin 'https://wheel.rprokhorov.ru/api/sessions?session=<session_id>'
```

В `curl` кириллицу нужно передавать через `--data-urlencode`, иначе запрос
уйдёт битым. Браузер кодирует параметры сам.

## Содержимое списков

**Сейчас собираются сами варианты из колеса** (`items_text`) для анализа
использования. Не больше 30 позиций, каждая обрезается до 60 символов.

Плашка в футере сайта сообщает о сборе статистики и вариантов. Если сбор
текстов будет отключён, нужно изменить отправку в `js/analytics.js` и
обновить формулировку в футере.

Рядом с текстами считается профиль списка — он останется полезен и после
того, как тексты отключат.

| Признак | Что показывает |
|---|---|
| `n`, `len_avg`, `len_min`, `len_max` | размер списка и длина вариантов |
| `looks_like_names` | короткие слова с заглавной — почти наверняка имена людей |
| `pct_cyrillic`, `pct_latin` | язык |
| `pct_emoji` | украшают ли варианты эмодзи |
| `pct_one_word` | имена или формулировки задач |

Коллектор пропускает только эти ключи и числовые значения; числовые строки
преобразует в числа, остальные строки отбрасывает.

## Хранение

В базе есть `events` с сырыми событиями, `daily_rollup` и `daily_breakdown`
с суточными агрегатами, а также служебная `meta`. Ночной `rollup` заполняет
агрегаты, но текущие `/api/stats` и `/api/sessions` читают `events`.
Удаление сырых событий сейчас удалит их из панели, даже если агрегаты сохранены.

При `IP_RETENTION_DAYS=0` IP хранится бессрочно. Положительное значение
включает очистку IP у старых событий во время ночного `rollup`; для разового
запуска:

```bash
# разово обнулить IP у событий старше 90 дней
docker compose exec collector sh -c 'IP_RETENTION_DAYS=90 node rollup.js'

# или разово обнулить всё сразу
docker compose exec collector node -e "
  const D=require('better-sqlite3');
  const db=new D(process.env.DB_PATH);
  console.log(db.prepare('UPDATE events SET ip = NULL').run());
"
```

`org_id` считается **в момент записи**, а не выводится из IP при чтении, поэтому
удаление IP не ломает ни группировку, ни историю. Обратный порядок не сработал
бы, поэтому пишем оба поля сразу.

## Приватность

- `localStorage` и `sessionStorage` вместо cookie
- Уважаем Do Not Track, есть явный отказ через `?analytics=off`
- Статистика закрыта Basic Auth

## Эксплуатация

```bash
docker compose logs -f collector
docker compose exec collector node rollup.js            # досчитать вручную
docker compose exec collector node rollup.js 2026-08-26 # пересчитать день
curl -u admin 'https://wheel.rprokhorov.ru/api/stats?days=30'
```

Резервная копия базы (безопасно при работающем коллекторе):

```bash
docker compose exec collector node -e "
  const D=require('better-sqlite3');
  new D(process.env.DB_PATH).backup('/data/backup.db').then(()=>console.log('готово'));
"
mkdir -p ../wheel-backups
docker compose cp collector:/data/backup.db "../wheel-backups/analytics-$(date +%F).db"
```

Резервные копии и `.env` храните вне репозитория: они содержат данные
пользователей и настройки доступа.

## Переменные окружения

| Переменная | Значение |
|---|---|
| `ORG_SALT` | постоянная соль для `org_id`, **менять нельзя** |
| `DASH_USER` / `DASH_PASS` | доступ к панели, статистике, журналу сессий и JS графиков |
| `HOST` | адрес прослушивания, по умолчанию `0.0.0.0`; для локальной проверки `127.0.0.1` |
| `IP_RETENTION_DAYS` | `0` — хранить IP бессрочно |
| `DB_PATH` | путь к базе, по умолчанию `/data/analytics.db` |

## Что не покрыто

`asn_org` (название провайдера или компании) в схеме есть, но пока не
заполняется: для него нужна база ASN или reverse-DNS в момент запроса.
Гео определяется по `geoip-lite` и **приблизительно** — VPN и корпоративные
прокси смещают картину, так что для «в каких странах вообще пользуются» этого
хватает, а для точных выводов нет.

## Защита HTTP в 1.6.3

Коллектор работает на Node.js 24+ под UID/GID 1000. В Compose `TRUST_PROXY=1`
и `SITE_ORIGIN=https://<домен>` задаются автоматически; Caddy перезаписывает `X-Real-IP`.
Не публикуйте порт 8081 при включённом доверии к прокси. Без прокси заголовки
IP игнорируются, адрес берётся из соединения.

`/api/e` принимает только POST с `application/json`, до 64 KiB и 50 событий.
Неверные данные получают 400/413/415, чужой Origin — 403. Код 204 означает,
что допустимые события записаны. Ограничение: 600 запросов/минуту с адреса,
6000 запросов/минуту на процесс; превышение — 429 с Retry-After.

После 30 неуспешных проверок пароля за минутное окно следующие попытки
блокируются до конца окна. Есть также общий лимит 1000 неуспешных проверок
на процесс в минуту. Ответы панели не кешируются. Хронология ограничена
1000 событиями; `truncated=true` явно сообщает о сокращении выдачи.

и [инструкция выпуска](../docs/release-freeze.md).

# Эксплуатация production

Обновлено 16.10.2026: размещение и мониторинг — по проверкам 12–13 октября, исправление передачи IP — по проверке 16 октября. При следующих изменениях перепроверить действующее состояние; это описание конкретной установки v1.6.3.

## Текущее размещение

Публичный `https://wheel.rprokhorov.ru` работает на VPS во Франции после переноса с NL. DNS переключён пользователем. Приложение не обновлялось: сохранены те же образы v1.6.3 сайта, collector/rollup и proxy. Рабочий каталог на VPS `/opt/wheel-of-fortune`, контейнеры wheel-site, wheel-collector, wheel-rollup, wheel-caddy. Существующий VPN-сервис VPS сохранён.

База статистики — том `wheel-of-fortune_analytics_data`, файл `analytics.db`; UID 1000, каталог 0700, файл 0600. Перед переносом остановлены старые collector/rollup, перенесён согласованный SQLite-снимок; подтверждено сохранение 1580 исторических событий и проверена запись/чтение с очисткой только синтетического события. Число датировано переносом. Сохранены существующие ORG_SALT и доступ к статистике. Значения `.env`, реквизиты и сертификатные private keys не хранить в репозитории.

Старый NL временно оставлен HTTPS-прокси на Францию для закэшированного DNS. Его collector/rollup остановлены: только Франция пишет статистику. На новом Caddy forwarded headers доверяются только точному адресу старого прокси. Удаление старого VPS и архивов отдельно не выполнялось.

## Проверки и мониторинг

Подтверждены валидный HTTPS, HTTP 200 сайта и `/api/health`, CSP/HSTS, 401 без авторизации `/api/stats` и 200 с существующим входом. Проверены домашний WAN и независимый LT, а также HTTPS-мост старого NL. Это не гарантия доступа из всех сетей. Блокировка NL конкретным ведомством не установлена.

Мониторинг находится вне wheel, в проекте `vpn-monitor` на домашнем сервере: Blackbox проверяет публичный DNS, TLS, HTTP 200, title главной страницы и `ok` API раз в 15 секунд. Ошибка дольше двух минут вызывает алерт; также проверяется истечение сертификата менее чем через семь дней. [Grafana wheel](https://grafana.lan/d/wheel-availability/) доступна в домашней сети.

Alertmanager доставляет сбой и восстановление через Hermes в существующие личные Telegram и Mattermost без LLM. Тестовые отправки обоих состояний подтверждены. Продолжающийся сбой напоминается раз в час. При недоступности домашнего сервера/его интернета доставка не гарантируется; независимого внешнего мониторинга пока нет.

## Управление и откат

16.10.2026 исправлена передача IP в production Caddy: `header_up X-Real-IP {http.request.client_ip}` заменено на `header_up X-Real-IP {client_ip}`. Верный полный placeholder — `{http.vars.client_ip}`. Некорректное значение приводило к сохранению адреса контейнера Caddy `172.18.0.5` через fallback collector. Доверие только старому NL-прокси сохранено. Резервная копия на VPS: `/opt/wheel-of-fortune/caddy/Caddyfile.bak-ipfix-20261016T083816Z`. Конфигурация прошла `caddy validate`, перезапущен только `wheel-caddy`. Два HTTPS-запроса с самого VPS через публичный адрес записали публичный IP VPS; поддельные X-Real-IP/X-Forwarded-For были проигнорированы. Обе синтетические записи удалены. Сайт и health вернули 200, закрытая статистика без авторизации — 401. Исторические записи не исправлялись.

На VPS: `cd /opt/wheel-of-fortune && docker compose ps`. Перед новым deploy сделать согласованную копию SQLite, закрытой конфигурации и сохранить версии образов. Не менять ORG_SALT при переносе. Не выполнять `docker compose down -v` при сохранении статистики.

После новых записей на Франции возврат к старому VPS требует согласованного обратного переноса свежей базы и остановки записывающих процессов. Простое восстановление старого снимка потеряет новые события. Мониторинг откатывается отдельно от сайта; базу wheel при этом не восстанавливать.

Точные IP, датированные checkpoint и закрытые серверные расположения резервных копий описаны в личном инфраструктурном документе `Домашний сервер/Wheel — размещение и мониторинг.md`. Конфигурация и инструкция мониторинга: `~/projects/vpn-monitor/monitoring/README.md`. Разовый перенос не требует нового релизного тега приложения; этот документ не заменяет [проверки нового релиза](release-freeze.md).

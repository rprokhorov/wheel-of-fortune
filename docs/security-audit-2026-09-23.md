# Проверка безопасности перед заморозкой 1.6.3

Дата: 23 сентября 2026. Исходная версия: 1.6.2, коммит `e9472fd`.
Изменения подготовлены в `security/freeze-1.6.3`.

**Результат:** подтверждённые проблемы кода исправлены; локальные проверки и
релизный CI обеих архитектур пройдены. [v1.6.3](https://github.com/rprokhorov/wheel-of-fortune/releases/tag/v1.6.3)
развёрнута в production 23 сентября 2026 года, проверки целевой установки по
[инструкции](release-freeze.md) завершены успешно.

  проверил HTTPS через Caddy, CSP/HSTS, 401 без авторизации, запись и чтение события,
  защиту от подставленного IP, отсутствие списка в логах, SQLite backup/integrity_check,
  rollup и переход тома root → UID 1000 с сохранением данных.

  сайт, окончательный коллектор и `wheel-proxy` — **0 HIGH/CRITICAL**.
  Более низкие уровни этой проверкой не используются как критерий блокировки.
- Gitleaks: исходная Git-история, **26 коммитов**, и все подготовленные файлы
  (включая новые) — секретов не найдено.
- actionlint: workflow-файлы прошли проверку; `npm run check:release` согласовал
  версии приложения, коллектора, lock-файлов, аналитики, примера окружения и release notes.
- Локальные и CI-сценарии использовали изолированные временные данные.

  обязательные тесты, Compose smoke и Trivy HIGH/CRITICAL пройдены для всех трёх

- На production проверены загрузка закреплённых образов, здоровье всех сервисов,

  отсутствие опубликованных портов backend и отключение административного API Caddy.

## Практические границы результата

Проверка охватывает репозиторий, зависимости, Docker, CI и сценарии HTTP/браузера
на локальной и целевой установках. Это не нагрузочный тест и не проверка всего
production-сервера. Полный аудит firewall, оценка стойкости действующих паролей
и резервное копирование по расписанию в объём работы не входили.

Публичный API остаётся доступен для поддельных событий и распределённого спама.
Сырые события хранятся без автоматического удаления; IP и тексты не являются
анонимными. Это существующий режим продукта, сохранённый аудитом. Владельцу остаются
контроль диска, решение о сроках хранения и обслуживание резервных копий.

Функциональность замораживается, обновления безопасности продолжаются:
новые уязвимости могут появиться после этой даты. Перенос тегов и отключение
проверок ради прохождения CI не входят в процедуру выпуска.

Развёртывание именно этих версий отдельно подтверждено на целевой установке.
